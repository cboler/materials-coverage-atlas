# Materials Coverage Atlas

An interactive d3.js atlas of the [Materials Project](https://materialsproject.org) database.
Every material is placed on a 2D map by UMAP over composition and property features, colored by
a rule-based candidate category, and can be re-colored by overlays that show where the database's
coverage is thin.

- **Categories**: structural (metallic/alloy and mineral/ceramic), energy, electronic/optical,
  magnetic, unclassified. The rules are
  documented in [`pipeline/categories.py`](pipeline/categories.py) and shown in the app.
- **Overlays**: element abundance, element cost, experimental vs. theoretical, elastic-data
  coverage (which entries lack bulk/shear moduli), and newer entries (added ~2020 onward, split
  by whether they land in sparse or crowded parts of feature space), and distance from stiffness
  data (how far a stiffness prediction would have to extrapolate; a coverage indicator, not a
  prediction).
- **Anchors**: calcite, gypsum, portlandite, alite, belite, quartz, corundum, iron and aluminum
  are pinned and labeled as reference points.
- **Region labels and density contours**: islands of the map are named by their dominant chemistry
  ("Li halides", "Sr–Ca nitrides", "Mn–Fe oxides"), and contours show where materials concentrate.
- **Find similar**: each anchor lists its nearest materials by composition and properties, marking
  which have elastic data (e.g. portlandite's neighbors are cement hydrates such as katoite and
  Friedel's salt, and only 2 of 20 have moduli).
- **Property profiles**: a parallel coordinates view with brushing. Every material is a line across
  category, origin, band gap, formation energy, hull energy, moduli, cost and abundance. Dragging a
  range on any axis filters both the lines and the map, and "no data" / "unphysical" slots on
  each axis make coverage and data-quality gaps visible.
- **Shareable figure**: `public/figures/coverage-headline.{png,svg}`, regenerated by the build
  (`pipeline/figure.py`) from `atlas.json`: iron's vs portlandite's 20 nearest compounds and how
  many have stiffness data, plus the structural-candidate coverage number, with MP attribution.
- **Coverage table**: per category, the share of entries that are experimentally observed, have
  elastic data, or have cost data. The structural rule admits entries for having elastic data,
  so its stiffness share is marked as built in; a separate **structural candidates** row (a
  moduli-blind rule: stable, earth-abundant oxides and metals) gives the comparable number.

Built on [angular-pwa-starter](https://github.com/cboler/angular-pwa-starter): Angular 22, static
hosting on GitHub Pages, installable PWA.

## How it fits together

```
Materials Project API ──► pipeline/ (Python, run locally) ──► public/data/atlas.json ──► Angular + d3 app
                              │
                              └─ pipeline/cache/ (git-ignored local API cache)
```

The site is static. The Python pipeline runs on your machine, and its output
(`public/data/atlas.json`) is committed, so the deployed site never calls the API and never needs
your key.

### 1. Generate the data

Requires Python 3.11+ and a Materials Project API key in `MP_API_KEY`.

```bash
python -m venv .venv
.venv/Scripts/activate        # macOS/Linux: source .venv/bin/activate
pip install -r pipeline/requirements.txt
python pipeline/build_atlas.py
```

- The first run pulls summary data for every material (formula, elements, band gap, formation
  energy, energy above hull, theoretical flag, magnetic ordering, bulk/shear moduli, symmetry,
  density) and caches it in `pipeline/cache/summary.parquet`. Later runs read the cache and
  never call the API. Pass `--refresh` to re-pull.
- The UMAP embedding is cached too, keyed by the feature matrix and UMAP parameters, so changing
  category rules does not re-run UMAP.
- `--sample 20000` embeds a random subset (anchors are always kept) for fast iteration.
- Run the rule tests with `pytest pipeline`.
- On Python 3.15, `mendeleev` still declares `<3.15`. It is pure Python and works fine; install
  it with `pip install --ignore-requires-python "mendeleev>=0.17"` after installing the rest.

**Or build it in GitHub Actions.** Add your key as the `MP_API_KEY` repository secret, then run
**Actions → Build Atlas Data**. The workflow runs the pipeline, commits `public/data/atlas.json`,
and redeploys Pages. The API pull and embedding are kept in the Actions cache between runs.

### 2. Run the app

```bash
npm ci
npm start
```

Open `http://localhost:4200/`. Without `public/data/atlas.json` the page shows setup instructions.

## Using the atlas

- **Scroll or pinch** to zoom and **drag** to pan. **Reset view** restores the full map.
- **Hover** a point for a summary. **Click or tap** it to pin a card next to it with its
  Materials Project link (current and former ID), "Show similar" for landmarks, and a jump to
  the full details. The card stays open while you zoom or move the pointer; close it with × or
  Esc.
- **Overlay buttons** recolor the map. **Legend entries** hide or show a group. With five
  categories on one scatter, no palette keeps every pair distinct under color-vision deficiency,
  so isolating groups from the legend is the reliable way to compare them.
- **Construction anchors** in the side panel (or on the map) select a reference material and open
  its **Similar to …** panel: the nearest formulas in feature space (not map distance), with
  polymorphs grouped and elastic coverage marked. Sort by similarity or put entries with elastic
  data first; neighbors are ringed on the map.
- **Contours** and **Region labels** toggle in the toolbar. Contours follow the legend: hide every
  group but one to see that category's shape. Region labels appear as you zoom in.
- **Property profiles**: drag along any axis to keep only lines in that range; brushes on several
  axes combine (AND). Drag into an axis's _no data_ slot to find entries missing that property, or
  its _unphysical_ slot to find broken elastic fits. Click an axis outside its brush, or use
  **Clear filters**, to reset. The map mutes everything that doesn't match. With more than 12,000
  matches, a stable random sample of lines is drawn (the header says so); counts are always exact.

### Caveats

- Categories are screening heuristics on computed values, not property predictions. MP band
  gaps are GGA/GGA+U and typically underestimate experiment.
- Magnetic ordering comes from MP calculations that are initialized ferromagnetic, so many
  transition-metal compounds report FM even where experiment finds antiferromagnetism. The
  magnetic rule therefore only counts metallic FM/FiM entries and insulating ferrimagnets;
  insulating "FM" results are treated as artifacts.
- Elastic moduli exist for only a small fraction of entries. "Structural" is verified where
  physical moduli exist, and inferred otherwise from the structural-candidate rule (stable,
  earth-abundant, and either a wide-gap oxide or a structural-metal alloy). Unphysical fits,
  such as aluminum's negative shear modulus, count as no data. The legend, detail card and
  coverage table show which basis applies. Because the verified path needs elastic data, the
  structural category's stiffness share is partly built in; the structural-candidate row is the
  comparable number.
- Both structural paths require element cost ≤ $100/kg and every element ≥ 10 ppm in Earth's
  crust; without that gate the stiffness path was dominated by rare-earth and precious-metal
  intermetallics. The same floor excludes W and Mo (about 1.2 ppm), so tungsten carbide is not
  structural here. Magnesium misses the 25 GPa shear cut (24.4 GPa in MP).
- The battery-electrode rule does not require a band gap, because several real electrodes
  (LiNiO₂, LiTiS₂) are metallic in GGA. It requires an anion framework, a meaningful working-ion
  fraction, and no spectator cations instead. Against MP's 6,847 insertion electrodes it catches
  86% of the intercalated compounds within its 0.05 eV/atom stability window (31% of all, since
  most sit above the hull). Precision is about 50% against an approximate negative set (stable
  compounds with a working ion that never appear as an electrode framework); some of those are
  real but uncomputed electrodes, so treat it as a lower bound. The pipeline recomputes both
  (`pipeline/electrodes.py`) and the app shows them under Category rules.
- Materials Project publishes no per-entry marker of machine-learning origin; GNoME-derived
  entries are an access-controlled batch and are not in the public data or this atlas.
  Provenance `created_at` dates are mostly bulk-rebuild stamps (88% of entries), so the
  newer-entries overlay orders entries by their old numeric ID, which was assigned as entries
  were added. On MP v2026.09.28, 12.8% of the 13,441 newer entries land in sparse regions
  (25% would match the older spread): they mostly crowd existing clusters.
- Element cost is the mass-weighted raw element price. It ignores processing, so treat it as a
  floor. Abundance is the crustal abundance of the scarcest element in the formula. Both come
  from the `mendeleev` element table.

## Commands

| Command                          | Purpose                                                 |
| :------------------------------- | :------------------------------------------------------ |
| `python pipeline/build_atlas.py` | Build `public/data/atlas.json` (cached after first run) |
| `pytest pipeline`                | Category rule tests                                     |
| `npm start`                      | Angular dev server                                      |
| `npm test`                       | Vitest unit tests                                       |
| `npm run lint`                   | ESLint                                                  |
| `npm run format:check`           | Prettier check                                          |
| `npm run build:pages`            | Production build + GitHub Pages 404 fallback            |
| `npm run e2e`                    | Playwright smoke tests (phone, tablet, desktop)         |

## Deployment

Pushing to `main` builds and deploys to GitHub Pages via `.github/workflows/deploy.yml`. Set
**Settings → Pages → Source** to **GitHub Actions** once. The base href is resolved from the
repository name automatically.
